# CoastalTutor implementation status

This short file is the working index. **The latest user-approved decisions in chat take precedence over older design documents.** Detailed audits and architecture notes remain historical references unless this file or a later chat confirms them.

## Product map

- **School Learning / China K–12:** CoastalTutor course path and knowledge graph drive sequential learning; generate interactive classroom lessons through the integrated OpenMAIC classroom engine. China is the first delivery priority.
- **School Learning / BC:** BC course targets and progress live in the dedicated BC course board, separate from the three-entry learner home. The board is available from School Learning → BC Courses.
- **Personal AI Tutor:** integrated DeepTutor, with CoastalTutor branding and the same platform learner/workspace identity as School Learning. Preserve its full native learner-facing tutoring, learning-path, practice, mistake-review, profile, and memory capabilities; do not constrain it to the School Learning lesson format.
- **Interactive Classroom:** integrated OpenMAIC with CoastalTutor branding and shared platform identity. Preserve its full native classroom creation and interaction capabilities; School Learning's curriculum lesson contract applies only to School Learning.
- Moodle is deferred. Revisit only when a school needs LMS roster, gradebook, or LTI interoperability.

## AI and billing decisions

- A learner with their own compatible key uses BYOK. Their key is never silently replaced by a platform-paid key.
- A learner without BYOK uses the configured platform-hosted model; provider details stay out of the learner-facing product UI. During tester onboarding SiliconFlow is the temporary primary, with DeepSeek as the planned next primary.
- Billing and usage limits are a later rollout phase. `PLATFORM_AI_ENFORCE_USAGE_LIMITS=false` keeps student testing unblocked; retain the configurable USD 25 cap and enable enforcement before paid/general release. BYOK does not consume Platform AI allowance.
- The user explicitly approved the existing SiliconFlow key as the temporary **primary** Platform AI provider for private testing. This is an explicit provider setting, not an automatic fallback. Switch to DeepSeek when its key is ready. Do not enable SiliconFlow as a general commercial SaaS fallback without the separate forwarding-terms review.
- Only text teaching is required for initial launch; optional media providers must not block ordinary lessons.

- **China course mistake handoff:** incorrect course attempts remain recorded against CoastalTutor's curriculum mastery, and the learner can continue in their same-identity DeepTutor chat. A signed, short-lived SSO claim carries the question, selected answer, grade and topic into a one-time HttpOnly cookie bound to that learner ID; DeepTutor prefills the tutor composer without sending automatically. The prefilled request asks the tutor to coach step by step, give a similar check question, and save the mistake through its native question-bank tool. That tool is available before the learner's first saved question. No answer explanation is sent in an incorrect-attempt response.
- **China course interaction reliability:** search is debounced, outdated catalog/detail responses cannot overwrite newer selections, the lesson drawer closes with Escape and locks background scrolling, numeric grade metadata restores correctly, and an empty filter has a clear-reset action. The accepted learner/parent timeline will read authorized summaries from both systems rather than copy raw histories. Shared curriculum lesson caching is implemented in the BC and China routes: it hashes curriculum identity plus the exact lesson requirement and generation schema, gzip-compresses complete classroom files into private Supabase Storage, and keeps only metadata in Supabase Postgres. Cache hits create fresh learner sessions and bypass model use; answers, completion, and mastery stay learner-specific. A live China course generation and immediate reuse check succeeded: the second session opened the same classroom ID without another model generation. Media-enabled lessons bypass the shared cache. The production schema/bucket migration was applied in Supabase project `xattfglcjiojuozvqsjw`. Curriculum lesson model responses are capped at 4,096 tokens and one generated widget per lesson. A follow-up makes progress count distinct generated classroom artifacts, so failed attempts and repeat opens do not inflate the lesson count.
