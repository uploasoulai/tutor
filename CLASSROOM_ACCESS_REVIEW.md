# Classroom asset access review — 2026-11-11

Scope: CoastalTutor classroom playback, local generated media, generation results, prepared trials, shared curriculum artifacts and browser exports. This is a targeted source/browser review, not an audit of the separate Tutor runtime or every upstream media service.

| Surface | Current boundary / evidence |
| --- | --- |
| `/api/classroom` | Authentication plus `readClassroom(id, user.id)`. A private record belonging to another learner returns nothing and cannot fall through to shared cache. Writes cannot overwrite another owner's ID. Existing ownership regressions cover these cases. |
| `/api/classroom-media/:id/...` | Fixed this round: authenticate and use the same classroom authorization before resolving files. Missing and unauthorized media both return 404. Existing traversal/symlink protection remains; success and errors use private/no-store. Tests cover anonymous/non-owner denial before filesystem access, authorized streaming, JSON rejection, traversal, symlink escape and missing files. |
| `/api/proxy-media` | Fixed this round: sign-in required, existing SSRF and redirect denial retained, bounded fetch and private/no-store response. No platform cookies or authorization headers are forwarded to the supplied remote URL. Upstream exceptions and signed media URLs are not returned or logged. |
| Classroom HTML and thumbnails | Fixed this round: script execution remains sandboxed without `allow-same-origin`. Real renderer browser checks block parent DOM and storage access while preserving click controls and the existing targeted teacher postMessage bridge. Mobile reviewed grouping/reset also passes inside the actual renderer. |
| Generation job reads/retries | Existing authenticated owner-bound store reads. Polling exposes selected progress/result fields, not persisted generation inputs or credentials. Generic classroom creation uses an explicit input allowlist, so a caller cannot supply the server-owned shared-cache descriptor. |
| Shared curriculum artifacts | Ready compressed artifacts use a private bucket, checksum validation and an authenticated classroom route. China requirements are assembled from the server curriculum graph; BC requirements use the curriculum/blueprint and selected teaching style, without student IDs, account emails, attempts or conversations. Learning records are stored separately. A prompt/structure check is not proof that arbitrary AI-generated HTML has passed educational review. |
| Prepared Grade-2/Grade-3 media | Public static authored teaching assets contain no learner information. Grade-2 entry is shared across signed-in roles; student bookmarks/checks remain private and parent/teacher/admin preview makes no learner API calls. Public static media is intentionally distinct from private student-generated media. |
| ZIP/PPTX exports | Existing client-side export reads the currently loaded stage/scene and browser-local media; no separate server export-by-ID access path was found. This review does not claim account isolation of all legacy browser-local/imported content on a shared browser profile. |

Remaining limits: an upstream provider may return its own bearer media URL; platform authorization cannot revoke copies already held outside the platform. Sandbox origin isolation does not itself block all outbound network traffic. Generated-widget network policy, other generic preview surfaces, legacy browser-local account switching and the separate Tutor runtime need their own review. Do not describe this patch as complete platform privacy certification. No public-sharing toggle or database migration is introduced.
